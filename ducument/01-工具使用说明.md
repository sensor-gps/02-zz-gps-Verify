## 功能概述

本工具提供 Python 图形界面，提取 UBX NAV-PVT 原始导航数据，在 GPS 周内时间 iTOW 上对比最多三路 GPS，并计算速度信号延迟。

- 选择 GPS1 和 GPS2，可直接计算 GPS2 相对 GPS1 的延迟，无需外部真值。
- 加载 ULog 真值后，可分别计算各 GPS 相对真值的延迟；GPS1 必须选择，用于建立时间映射。
- 同时加载真值和 GPS1、GPS2 时，两类结果都会输出。选择 GPS3 不影响两路比较。
- 支持 RTCM 星历接收覆盖情况分析。
- 支持自动解析 NAV-SAT / NAV-SVINFO，按 iTOW 对齐比较使用卫星数和平均载噪比，导出双图与 CSV。
- 支持相对 ULog 的动态速度及去初始位置偏置、逐轴扣除平均偏差的轨迹精度评估，默认按各路 NE 时延补偿后再统计，仅输出指标表及 CSV。

## 安装与运行

需要 Python 3、Tkinter 及依赖包。在仓库根目录运行：

```sh
python -m pip install -r requirements.txt
python gps_delay_analyzer.py
```

选择一至三个 GPS 原始日志文件，例如 `.log`、`.ubx` 或包含 UBX 数据的二进制文件。空输入框会被跳过；两路比较要求填写 GPS1 和 GPS2。

需要真值时，选择 `.ulg` 或 `.ulog` 文件。当前界面虽然仍显示旧的“VIO 真值 ffc.csv”文字，但实际入口要求 ULog，不接受 CSV 真值。

程序校验 UBX 校验和，提取 NAV-PVT 字段并过滤无效定位，再按 100 ms 时间格去重，每格最多保留一条记录。提取结果写入本地 `analysis_output/*.pvt.csv`。

## 对齐与延迟计算

不加载 ULog 时，第一路已选择的 GPS 提供绘图参考时间轴。其他 GPS 按最近 iTOW 在配置容差内匹配，容差单位为毫秒，零表示精确匹配。一条 GPS 记录可能匹配多个参考时刻；光标读数保留原始 iTOW。

绘图最近邻匹配与延迟计算分别执行。延迟搜索使用去重后的数据，在 ±2000 ms 范围内按 10 ms 步长扫描，使用线性插值及去均值归一化相关系数选择最优延迟。两路 GPS 比较会在共同有效时间范围内按 20 ms 均匀网格重采样，并限制单次插值跨度不超过 1 s；真值比较仍使用真值时间轴和原有线性插值。输出北向、东向联合速度延迟，以及有效单通道的延迟、相关系数和均方根误差。两路 GPS 互比的单通道只含 N/E/D 速度，不输出水平地速 `speed`；该通道仅用于 GPS 相对真值的比较。

GPS2 相对 GPS1 延迟为正，表示 GPS2 滞后；为负，表示 GPS2 超前。详细公式参见算法文档。

## 图表操作

- 分页显示不同导航字段，每路均可填写图例名称；留空时使用日志文件名，填写后使用自定义名称。
- 空白区域按住鼠标左键拖动：框选缩放。
- 鼠标中键拖动：平移；滚轮：缩放。
- 空格键或 Home 键：恢复初始视图。
- 鼠标右键：交替放置 A、B 光标。
- 在光标附近按住左键拖动：移动光标并更新测量。
- A/B 键：选择活动光标；左右方向键：移动光标。
- 读数包括插值数值、时间差、数值差及最近匹配样本的原始 iTOW 差。
- 标记大小随可见点密度调整，保留所有实际采样点标记。

## ULog 真值与时间映射

当前主流程读取 `drone_fusion` 的位置、速度和航向角，以及 `fusion_gps` 航向角，逐时刻转换到北、东、地坐标系。

延迟分析和精度评估都提供“固定 yaw_diff(°)”输入框和“估计 yaw_diff”复选框。启动时固定值为空、复选框默认勾选，因此默认由 GPS1 与 `drone_fusion` 水平速度序列估计一个固定 `yaw_diff`；固定值有值时优先使用；取消勾选且固定值为空时逐时刻计算 `drone_fusion.yaw − fusion_gps.yaw`。固定值与估计开关都不写入历史配置，每次启动恢复为“固定值为空、估计打开”。实际旋转角均为 `−yaw_diff`。详见 [yaw_diff 速度估计说明](06-yaw_diff速度估计说明.md)。

程序使用 ULog 中 `sensor_gps` 的速度及经纬度与 GPS1 原始记录做唯一身份匹配，建立 ULog 启动时间到 GPS1 iTOW 的偏移。GPS2、GPS3 使用各自 iTOW 对齐共同时间轴。

结果依赖坐标含义、角度单位和时间映射的正确性，是相对于构造参考的信号延迟，不能直接解释为绝对串口或射频延迟。

## 历史 CSV 解析模块

`pylib/fusion_csv_reference.py` 保留历史 FFC CSV 解析逻辑，当前主界面不调用此模块。

该模块读取 `sensor.gps.velE`、`sensor.gps.velN`、`preint.vel.x` 和 `preint.vel.y`，在 ±2 s 范围内以 10 ms 步长搜索延迟；对各候选延迟通过最小二乘估计二维航向角，选择北向、东向速度均方根误差最小的组合。旋转后的速度作为参考；有真北航向字段时，还会利用航向角差估计安装偏角。

该部分用于说明保留模块的用途，当前运行方式以 ULog 主流程为准。

## RTCM 星历检测

在左侧选择“RTCM 星历检测”，打开含 RTCM3 二进制内容的日志。`pylib/rtcm_ephemeris.py` 校验 CRC24Q，提取 GPS、GLONASS、Galileo、北斗、QZSS 等卫星系统的多信号观测消息（MSM）卫星掩码和星历卫星编号。

图表采用 10 秒窗口，显示三组数据：

- 实线：截至窗口结束，文件中尚未收到星历的已观测卫星数占该窗口观测卫星数的比例。
- 虚线：当前窗口内未发送星历消息的已观测卫星比例。
- 右轴背景柱状图：各窗口观测到的不同卫星数量。

GPS MSM 历元提供时间锚点。其他卫星系统消息和星历按文件顺序关联到前一个 GPS 历元。缺少可用 GPS MSM 锚点的日志会被拒绝。这是文件顺序的近似关联，不是独立接收时间戳。

此前收到的星历视为存在；程序不评估有效期、健康状态或录制前接收机已有缓存。虚线反映消息发送覆盖情况，不代表星历无效。统计导出到本地 `analysis_output/<文件名>.ephemeris.csv`。

## 本地数据管理

原始飞行日志、生成的分析文件、Python 缓存和 `.gps_delay_history.json` 历史配置已被 Git 忽略。历史配置可能包含本地路径，只保留在本地。

## 项目目录与启动入口

根目录仅保留一个 Python 启动脚本 `gps_delay_analyzer.py`。安装依赖后，双击该脚本（需要系统已关联 Python），或在任意工作目录使用该脚本的完整路径启动即可。

```text
项目根目录/
├── gps_delay_analyzer.py          主界面及唯一启动入口
├── requirements.txt              依赖清单
├── pylib/                        辅助模块包，无需单独运行
│   ├── __init__.py
│   ├── fusion_reference.py        ULog 真值转换
│   ├── yaw_estimation.py          由水平速度序列估计 yaw_diff
│   ├── fusion_csv_reference.py    历史 CSV 解析模块
│   ├── gps_timing.py              延迟计算
│   ├── cno_analysis.py            卫星载噪比对比
│   └── rtcm_ephemeris.py          RTCM 星历分析
├── ducument/                     中文文档
├── analysis_output/              本地分析结果，自动创建
└── .gps_delay_history.json       本地历史配置
```

主脚本通过 `pylib` 包导入辅助模块，不需要手工设置模块搜索路径。历史配置和分析输出都相对于项目位置保存，不随启动时的工作目录变化。移动或分发程序时，应保留主脚本与整个 `pylib` 文件夹的相对位置。

## 自定义图例名称

延迟分析和载噪比对比的每路 GPS 路径旁均提供“图例名称”输入框。填写名称时以去除首尾空白后的名称作为图例；留空或仅输入空白时，使用包含扩展名的日志文件名，不包含父目录路径。

自定义名称用于图表及延迟分析光标读数，载噪比 PNG 和 CSV 也保留对应名称。两种分析项目分别保存路径与图例名称，重启后自动恢复。GPS 编号仍用于计算关系和状态日志，不受显示名称影响。

对外分享图片时，可填写通用名称，避免文件名中的设备信息出现在图例中。
