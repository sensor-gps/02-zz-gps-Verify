# ULog 脱敏使用说明

编写日期：2026-11-18。

[返回文档目录](01-工具使用说明.md)

## 使用方法

运行主脚本，选择左侧“ULog 脱敏”项目，输入完整 ULog 和新文件保存路径，点击“生成并验证精简 ULog”。默认建议名称为原文件名加 `_sanitized.ulg`。输出文件必须不存在，且不能与原文件相同；原文件不修改。

任务在后台执行，完成后显示保留字段、样本数及前后文件大小。之后可在延迟和精度项目中选择新文件作为 ULog 真值，GPS 日志继续使用原来的文件，尤其应保持同一 GPS1 作为时间锚点。

## 保留字段白名单

| 主题 | 保留字段 |
| --- | --- |
| `drone_fusion` | `timestamp`、`position_x/y/z`、`velocity_x/y/z`、`yaw`；源文件存在时保留 `is_hori_valid`、`is_vert_valid`、`using_fake_fusion` |
| `fusion_gps` | `timestamp`、`yaw` |
| `sensor_gps` | `timestamp`、`veln`、`vele`、`veld`、`lat`、`lon` |

白名单字段保留原类型、原数值、原时间戳及原采样条数，不重采样、不平移时间。若存在多个同名主题实例，按当前真值加载器的选择规则使用最后一个同名实例，输出统一为实例零。

本功能针对当前主界面使用的 GPS1 身份匹配真值流程，不保留历史 CSV 或其他备用 ULog 主题。

## 删除内容与保留限制

从白名单数据重新构建最小 ULog，不直接复制原始二进制块。其他主题、其他字段、参数、设备信息、软件标识、日志文本、标记信息和丢帧事件均不写入新文件。

**此功能是分析所需字段的最小化精简，不是完全匿名化。** `sensor_gps` 经纬度用于现有 GPS1 身份匹配，必须保留，因此仍含地理位置。局部位置、速度、航向和原始时间戳也保留。输出文件名和保存目录由用户选择，不会自动改写其中的设备名称。

## 输出验证

写入临时文件后，通过 `pyulog` 重读，检查主题数量、字段白名单及所有保留数值逐项一致，并调用当前真值加载器验证保留字段的航向旋转和有效性筛选可用。脱敏验证沿用 `fusion_gps.yaw` / `drone_fusion.yaw` 路径，不进行速度序列 `yaw_diff` 估计，因此不需要 GPS1 速度序列。成功后才生成目标文件；失败时不留下正式目标文件。

已使用真实日志验证：原始与精简 ULog 搭配同一 GPS1 时，生成的参考数据、延迟结果及当前精度指标一致。源文件缺少必需主题或字段时明确报错，不用零值代替。

核心实现：`pylib/ulog_sanitize.py`。
